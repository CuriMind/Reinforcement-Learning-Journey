## 17. 信用分配：span / turn / 步骤

> **本章回答的问题**：多步任务只在末端给一个奖励，怎么知道"哪一步做对了"？步骤级优势与序列级广播的差别到底体现在方差还是偏差上？四种已发表的做法分别在用什么信号——它们能不能互相替代？

> **证据强度**：📙 单篇报告 —— 本章四个方法（StepPO / GVPO / ELPO / CARD）全部来自 2025–2026 的单篇工作，**均无独立复现**。因此本章的写法是：**给通用形式 + 各方法的"信号来源"对比**，具体公式以原文为准，本章不代为背书。

> **本章边界**：本章**集中所有多轮信用分配**。**不写**形式化（→第 16 章）；**不写**环境与验证器（→第 18 章）；**不写**序列级重要性比（→第 14 章）；**不写** token 级归一化（→第 13 章）。

---

### 17.1 问题的本质：一个奖励，$S$ 个决策

> **本节回答的问题**：为什么"末端一个奖励"在 $S>1$ 时一定会出问题？

设轨迹由 $S$ 步组成，只有末端奖励 $R$。序列级广播（GRPO 的做法，第 12 章）给每一步相同的优势：

$$
\hat A_s = R-\bar R\quad\text{对所有 } s=1..S
$$

**逐项读**：① 每一步拿到的是**同一个数**；② 这意味着"第 1 步选错工具"与"第 5 步算错数字"被赋予**完全相同的信用**。

**它什么时候致命**：

| 情形 | 后果 |
|---|---|
| 轨迹长且成功率高 | 大量"几乎全对"的轨迹被整体强化，包括其中的错误步骤 |
| 一条轨迹里既有对也有错 | 错误步骤被**正向强化**（因为末端对了） |
| 失败轨迹 | 正确的前几步被**负向惩罚** |

**第二个后果最隐蔽**：它会产生"**行为退化**"——模型学会"先做一堆无关但安全的操作，再碰运气"，因为无关操作与成功共享同一份奖励。

**形式化一点**：设每步有独立的"正确性" $z_s\in\{0,1\}$，末端奖励是 $R=\prod_s z_s$（全对才给分）。序列级广播下，某一步的梯度期望为：

$$
\mathbb E[\hat A_s]=\mathbb E\left[\prod_{s'}z_{s'}\right]-\mathbb E\left[\prod_{s'}z_{s'}\right]=0\quad\text{（在组内标准化后几乎总是 0 均值的）}
$$

**逐项读**：① 乘积形式意味着"只有全对才有正奖励"；② 于是所有步共享一个稀疏信号，**每一步的边际贡献被完全平均**。这就是信用分配问题在稀疏奖励下的严格版本。

> **工程提示**：如果你的 agentic 任务成功率在 20% 以下、且步数 > 5，序列级广播的学习信号会极度稀薄。**先降任务难度或提供中间可验证信号**，再谈算法。

**小结**：一个奖励配 $S$ 个决策，必然把"哪步错了"这个信息抹掉。所有信用分配方法都在回答同一个问题：**从哪再弄一个信号**。

### 17.2 通用形式：步骤级优势长什么样

> **本节回答的问题**：不谈具体方法，step 级优势的通用写法是什么？

标准做法是给每一步一个**局部回报**与一个**基线**：

$$
\hat A_s=\underbrace{\sum_{s'=s}^{S}\gamma^{s'-s}\,\tilde r_{s'}}_{\text{该步之后的累计回报}}-\underbrace{b_\phi(s_s)}_{\text{基线}}
$$

**逐项读**：① $\tilde r_{s'}$ 是**第 $s'$ 步的信号**——问题就在于它从哪来；② $\gamma$ 折扣；③ 基线可以是价值函数（$b_\phi=V_\psi$）、组内均值、或该步前缀的通过率。

**所有方法的差别只在这两处**：

| 差别 | 选项 | 代表 |
|---|---|---|
| **$\tilde r_s$ 从哪来** | ① 无中间奖励（$\tilde r_s=0,\ s<S$） | 纯 GRPO |
| | ② 步骤可验证（规则/工具判定） | VPR（第 18 章） |
| | ③ 步骤级偏好（人对/模型判） | StepPO |
| | ④ 从失败点反推（错误定位） | ELPO |
| | ⑤ 从专家批评蒸馏 | CARD |
| **$b_\phi$ 怎么算** | ① 价值网络 | VAPO（第 14 章） |
| | ② 组内均值 | GRPO |
| | ③ 前缀成功率 | 难度感知类 |

对应的策略梯度估计器（所有 step 级方法的共同外壳）：

$$
\nabla_\theta J=\mathbb E_{\tau}\left[\sum_{s=1}^{S}\hat A_s\,\nabla_\theta\log\pi_\theta\!\left(a_s\mid s_s\right)\right]
$$

**逐项读**：① 外层对轨迹求期望；② 每一步的优势**只乘该步动作的对数概率梯度**——这就是信用分配在数学上的落点：$\hat A_s$ 决定第 $s$ 步被强化还是被抑制；③ 若把所有 $\hat A_s$ 换成同一个数，就退化成序列级广播（17.1 节）。

**这张表就是本章的骨架**：不看名字，看它把哪个"旋钮"换掉了。

**方差—偏差的交换（必须理解）**：

$$
\operatorname{Var}\left(\hat A_s\right)\ \propto\ \frac{\sigma^2}{n_s}\quad\text{其中 } n_s=\text{覆盖第 } s \text{ 步的样本数}
$$

**逐项读**：越靠后的步骤，覆盖它的样本越少（因为前面的步骤已经把轨迹分叉了），所以 $n_s$ 随 $s$ 递减 → **方差随 $s$ 递增**。这就是"步骤级降低了偏差（能区分各步）却抬高了方差（每步样本少）"的定量来源。

> ⚠️ **常见错误**：以为"步骤级一定比序列级好"。它把**一个高偏差低方差**的估计器换成**低偏差高方差**的估计器——在样本不足时，后者可能更差。判定标准是"每步平均覆盖样本数"，不是"粒度越细越好"。

**小结**：step 级优势 = 局部回报 − 基线。所有方法的创新都在"局部回报从哪来"与"基线怎么估"两个旋钮上。下一节看四个方法各自换了什么。

### 17.3 四种范式：StepPO / GVPO / ELPO / CARD

> **本节回答的问题**：这四个名字各自治什么病？它们能互相替代吗？

**先声明**：以下只给**问题定位与信号来源**，具体目标函数以原文为准（📙 均未独立复现）。

**① StepPO：把偏好做到步骤上**

- **信号来源**：步骤级的偏好比较（哪一步更好）；
- **换掉的旋钮**：$\tilde r_s$ 从"无"变成"步骤偏好信号"；
- **直觉**：如果整条序列难以比较，但"这两步哪个更好"可以判，就把 DPO 式的成对比较下沉到步骤；
- **代价**：需要步骤级标注或可判定的步骤质量，**标注成本高**；
- **适用**：有清晰中间检查点的任务（如"检索到正确文档"这一步可判）。

**② GVPO：用组内方差做信号**

- **信号来源**：组内奖励的方差结构（哪一步的方差贡献大）；
- **换掉的旋钮**：$b_\phi$ 与权重的分配方式；
- **⚠️ 名称须核准**：检索到的同名为 *Group **Variance** Policy Optimization*，与第一版框架里的"过程可验证塑形"表述不符。本章按"组内方差"理解，**引用前必须核对原文**；
- **适用**：组内差异主要来自少数关键步骤的任务。

**③ ELPO：从"不可恢复的错误"反推**

- **信号来源**：错误定位——某一步之后，轨迹再也无法成功；
- **换掉的旋钮**：$\tilde r_s$ 用"是否成为不可恢复点"来定义；
- **直觉**：不需要每步都对，只需要找到**第一个致命错误**，给它负信用，它之前的步骤保留正信用；
- **代价**：需要能判定"从这步起已无救"，通常靠重试/回溯或环境判定；
- **适用**：有明显"一次错就完"结构的任务（如填表、参数化调用）。

**④ CARD：把专家批评蒸馏成步骤信号**

- **信号来源**：外部批评（critique）被蒸馏为步骤级的训练信号；
- **换掉的旋钮**：$\tilde r_s$ 来自更强的模型/专家的文字反馈，而非标量；
- **直觉**：标量奖励信息量太低，文字批评信息量高，但需要转成可训练的信号；
- **代价**：需要强模型作为批评者，成本高，且有"批评者偏见"。

| 方法 | 局部回报来源 | 需要什么额外资源 | 主要方差来源 | 适用结构 |
|---|---|---|---|---|
| 序列级广播（基线） | 无 | 无 | 信用混淆（偏差大） | 短轨迹、高成功率 |
| StepPO | 步骤偏好 | 步骤级标注/判定 | 标注噪声 | 有中间检查点 |
| GVPO ⚠️ | 组内方差 | 组采样 | 组大小 | 差异集中在少数步 |
| ELPO | 不可恢复点 | 重试/环境判定 | 判定准确率 | 一次错即失败 |
| CARD | 专家批评 | 强模型 | 批评者偏见 | 有强模型可用 |
| VPR（第 18 章） | 步骤可验证 | 规则/工具 | 验证器覆盖 | 步骤可自动判定 |

> **工程提示**：先问"我有没有一个**能自动判定的中间信号**"。有 → 优先用可验证的过程奖励（第 18 章的 VPR 路线），最便宜也最可靠；没有 → 再考虑偏好、批评、反推这三条贵路线。

**小结**：四种范式不是四个可比的方法，而是**四种信号来源**。选择的第一原则不是"哪个新"，而是"我手上有什么可判定的信息"。

### 17.4 与粒度账本的关系：为什么这章是 L3 的核心

> **本节回答的问题**：为什么第 0 章把"信用分配"标成 L3 的核心难点？

回到账本表的 L3 行：**状态 = 完整交互历史，动作 = 一次调用，时域 = 3–30 步**。这个组合有三个特征，共同制造了信用分配难题：

1. **时域中等偏长**（3–30）：序列级广播的偏差开始显著，但样本量还不够做精细估计；
2. **动作不可逆**：错误的代价不对称（调错 API vs 说错一句话）；
3. **中间状态可判定**（有时）：这是与 L4/L5 最大的不同——**L3 通常有工具或规则能判"这一步对不对"**。

所以 L3 的正确策略是：**尽量把"可判定"变成"可训练"**（第 18 章），而不是硬用 RL 去猜。这也是为什么本章反复强调"信号来源"而不是"算法优劣"。

**回填你的账本表**（第 0 章 0.2 节 · L3 行的"信用分配"与"标准修法"列）：

```
L3: 信用分配 = 核心难点 ✓
    标准修法：步骤级优势 ✓（本章）、过程可验证奖励（18 章）、
              不可恢复点定位 ✓（ELPO）、批评蒸馏 ✓（CARD）
    → 待补：环境侧约束如何替代奖励侧塑形（19 章）
```

---

**小结**：L3 的特殊性在于"中间状态常常可判定"——这是它比 L4/L5 好教的地方，也是它的解法应当优先"造信号"而非"猜信用"的原因。把可判定的东西变成可训练的，是这一层最划算的工程动作。

**本章收束**：① 本章把信用分配从"四个方法"还原成"一个通用形式 + 两个旋钮"（局部回报从哪来、基线怎么估），并给出方差随步数上升的定量来源；② 与下一章的接口是：既然最便宜的信号是"可判定的中间结果"，第 18 章就专门讲**环境与验证器怎么造出这个信号**；③ 留下的未解问题是**四种信号来源没有可比的评价基准**（📓），它会在第 23 章以"环境与数据的度量"的形式重新出现。
