## 3. 值迭代与策略迭代

> **本章回答的问题**：如果环境的规律（$P$ 与 $r$）已经知道，最优策略怎么算出来？"评估一个策略"和"改进一个策略"为什么能交替进行而不会循环？值迭代与策略迭代是同一种东西吗？

> **证据强度**：📕 教科书结论 —— 策略改进定理、策略迭代的有限步收敛、值迭代的 $\gamma^k$ 收敛率都有严格证明。★ 本章的证明可略读，但**"两者是同一个框架的两个极端"**这个结论必须记住。

> **本章边界**：本章只处理**已知模型**（planning）。**不写**无模型方法（→第 4 章）；**不写**函数逼近（→第 5 章）；**不重复**第 2 章的贝尔曼方程推导（只引用）。

---

### 3.1 "已知模型"意味着什么

> **本节回答的问题**：planning 与 learning 的分界线在哪？

第 2 章给出的两个贝尔曼方程里，$P$ 与 $r$ 是**已知函数**。此时你可以"在脑子里推演"而不必真的行动——这就是 **planning**。

| | Planning（本章） | Learning（第 4 章起） |
|---|---|---|
| 知道 $P,r$？ | 知道 | 不知道 |
| 数据从哪来 | 可以对 $P$ 任意查询（模拟） | 只能从真实交互得到 |
| 代价 | 算力 | 样本 + 算力 |
| 典型场景 | 棋盘游戏、模拟器 | 真实环境、LLM |

**这个区分很重要**，因为本章的算法（值迭代/策略迭代）在 LLM 上几乎不能直接用——你不知道"下一个 token 的分布"这个转移函数（第 9 章：token 级 MDP 的转移是确定性的，但奖励与终止你也不知道）。**但它的思想（评估 + 改进）是后面所有算法的骨架。**

**小结**：planning 与 learning 的分界是"是否已知模型"。本章算法在 LLM 上不直接可用，但它的"评估—改进"结构贯穿全课程。

---

### 3.2 策略评估：解方程还是迭代

> **本节回答的问题**：给定 $\pi$，怎么算出 $V^\pi$？

第 2 章给了两种视角，对应两种做法：

**做法一（解析）**：解线性方程组 $\mathbf v^\pi=(I-\gamma P^\pi)^{-1}\mathbf r^\pi$。代价 $O(|\mathcal S|^3)$。

**做法二（迭代）**：反复代入贝尔曼期望算子：

$$
V_{k+1}(s)\ \leftarrow\ \sum_{a}\pi(a\mid s)\sum_{s'}P(s'\mid s,a)\left[r(s,a,s')+\gamma V_k(s')\right]
$$

**逐项读**：① 对每个状态，用**上一轮的**后继价值更新；② 这等价于 $V_{k+1}=T^\pi V_k$；③ 它是压缩映射（第 2.5 节），所以 $V_k\to V^\pi$，误差按 $\gamma^k$ 衰减。

**为什么实践中都用迭代**：$|\mathcal S|$ 大时求逆不可行；而迭代的每一次是 $O(|\mathcal S|^2|\mathcal A|)$，可以早停（不需要精确解）。

$$
\left\|V_k-V^{\pi}\right\|_\infty\le\frac{\gamma^{k}}{1-\gamma}\left\|V_0-V^{\pi}\right\|_\infty
$$

**逐项读**：① 误差以 $\gamma^k$ 衰减；② 系数 $1/(1-\gamma)$ 放大初始误差；③ **它给出"要迭代多少轮"的估计**——$\gamma=0.9$ 时，约 40 轮就能把误差降到初始的 $1/100$。

> **工程提示**：策略评估用"固定轮数"而不是"收敛到阈值"更常见——因为外层策略迭代很快就不需要精确的 $V$。给评估设一个固定的 $k$（比如 10 轮），比设一个误差阈值更稳、更可复现。
> **工程提示**：策略评估不需要算到精确。实践中"评估到误差小于某个阈值就停"（截断评估）反而更好——第 3.6 节会说明，这恰好把策略迭代与值迭代连成了一个连续谱。

**小结**：策略评估可以用解析解或迭代。迭代更实用，且它的收敛率 $\gamma^k$ 给出"迭代多少轮"的定量依据。

### 3.3 策略改进：贪心为什么不会变差

> **本节回答的问题**：有了 $V^\pi$，怎么得到更好的策略？凭什么保证更好？

**贪心改进**：对每个状态选当前看起来最好的动作：

$$
\pi'(s)=\arg\max_a Q^{\pi}(s,a)
$$

**这里的核心定理（策略改进定理）**：若对所有 $s$ 有 $Q^\pi(s,\pi'(s))\ge V^\pi(s)$，则 $\pi'$ 不差于 $\pi$：$V^{\pi'}(s)\ge V^\pi(s)$。

**证明的骨架只有三行**（值得看一遍，因为它解释了"为什么能保证"）：

$$
V^{\pi}(s)\le Q^{\pi}\left(s,\pi'(s)\right)=\mathbb E\left[r+\gamma V^{\pi}(s')\right]\le\mathbb E\left[r+\gamma V^{\pi'}(s')\right]=V^{\pi'}(s)
$$

**逐项读**：① 第一步用"贪心不差于原动作"的假设；② 第二步展开 $Q$；③ **第三步是关键**——把 $V^\pi$ 换成 $V^{\pi'}$（因为已证 $\pi'$ 在每个后继状态也不差，归纳）；④ 最后一步回收到 $V^{\pi'}$ 的定义。

**为什么不会循环**：只要改进是**严格**的（某状态上真的更好），$V$ 就严格上升；而 $V$ 有上界（回报有界），所以策略序列不可能无限循环。**有限个确定性策略 + 严格上升 ⇒ 有限步收敛。**

**小结**：策略改进定理说明"对 $Q^\pi$ 贪心不会变差"，证明靠归纳。它是策略迭代能收敛的全部根据。

### 3.4 策略迭代：评估与改进交替

> **本节回答的问题**：把 3.2 和 3.3 接起来，会发生什么？

**算法**（一个循环）：

```
1. 策略评估：算 V^π（可以近似）
2. 策略改进：π ← greedy(V^π)
3. 若 π 不变，停止
```

**它的收敛性质**：

| 性质 | 内容 | 依据 |
|---|---|---|
| **单调** | 每一轮 $V$ 不降 | 策略改进定理（3.3） |
| **有限步** | 确定性策略有限，严格改进不能无限次 | 组合论证 |
| **最优性** | 停止时 $\pi$ 满足贝尔曼最优方程 | 不动点 |

**通常需要多少轮**？实践中**很少**——常常十几次迭代就收敛，远小于策略总数。这是它比"枚举策略"强的根本原因。

**代价在哪**：每一轮要做**完整的策略评估**（可能几十轮迭代）。如果状态多，这一步很贵。**这个代价正是值迭代要省掉的。**

**小结**：策略迭代 = 完整评估 + 一次改进，单调且有限步收敛，但每轮评估昂贵。下一节把"完整评估"砍成"一次"。

---

### 3.5 值迭代：把两步合成一步

> **本节回答的问题**：能不能不显式维护策略，直接迭代价值？

**做法**：每轮只做"一次评估 + 一次取最大"：

$$
V_{k+1}(s)\ \leftarrow\ \max_{a}\sum_{s'}P(s'\mid s,a)\left[r(s,a,s')+\gamma V_k(s')\right]
$$

**逐项读**：① 这就是贝尔曼**最优**算子 $T$；② 与策略评估的唯一差别是 $\sum_a\pi$ 换成了 $\max_a$；③ 于是它同时做"评估"与"改进"——**因为取最大就是贪心改进。**

**收敛**：$T$ 是压缩映射（第 2.5 节），所以 $V_k\to V^*$，且误差按 $\gamma^k$ 衰减。收敛后取贪心即得 $\pi^*$。

| 维度 | 策略迭代 | 值迭代 |
|---|---|---|
| 每轮做什么 | 完整评估 + 改进 | 一次评估 + 取最大 |
| 每轮代价 | 高（多次扫描） | 低（一次扫描） |
| 需要轮数 | 少 | 多 |
| 显式维护策略 | 是 | 否（收敛后再取） |
| 何时更优 | 状态少、$\gamma$ 小 | 状态多、只要 $V^*$ |

> **工程提示**：选值迭代还是策略迭代，看的不是"哪个更好"，而是**你要 $V^*$ 还是要 $\pi^*$**。只要 $V^*$（比如做评估或搜索）→ 值迭代；要策略且状态少 → 策略迭代。两者在总代价上常常相近。
**小结**：值迭代把"多次评估"压成"一次"，于是每轮更便宜、但需要更多轮。它与策略迭代在总代价上常常相近，选择取决于状态规模与是否需要策略。

### 3.6 截断策略迭代：两者其实是同一个框架

> **本节回答的问题**：如果把"评估几次"当成参数，会发生什么？

**广义策略迭代（GPI）**：评估 $k$ 次 + 改进一次，$k$ 是一个旋钮。

$$
k=1\ \Rightarrow\ \text{值迭代}\qquad k\to\infty\ \Rightarrow\ \text{策略迭代}
$$

**逐项读**：① $k=1$ 时每轮只评估一次就改进——这就是值迭代；② $k$ 很大时每轮几乎精确评估——这就是策略迭代；③ **两者不是两种算法，而是同一个框架的两个端点。**

**这张图是全课程的一个隐喻**：后面所有方法都可以放在这个框架里看——

| 方法 | 相当于 $k$ 取多少 | 章节 |
|---|---|---|
| 值迭代 | 1 | 本章 |
| 策略迭代 | $\infty$ | 本章 |
| TD / Q-learning | 用采样代替"精确评估"，$k=1$ | 第 4 章 |
| Actor-Critic | critic 持续评估，actor 每步改进 | 第 6 章 |
| PPO / GRPO | 同一批数据上评估多次（多 epoch），改进一次 | 第 7、12 章 |

**最后一行尤其值得注意**：PPO 的"多 epoch"恰恰是**在固定数据上反复评估**——它是截断评估的一种工程实现。**"评估—改进"这个循环从未消失，只是评估的精度与数据来源变了。**

**小结**：截断策略迭代把值迭代与策略迭代统一成"评估 $k$ 次 + 改进一次"的连续谱。后面所有算法都是这个框架的变体——区别只在"评估用什么数据"与"k 取多少"。

### 3.7 复杂度与"为什么这一章在 LLM 上用不上"

> **本节回答的问题**：这些算法的代价是多少？为什么不能直接用在 LLM 上？

**代价**：每轮扫描需要 $O(|\mathcal S|^2|\mathcal A|)$（对每个状态-动作遍历所有后继），轮数约为 $O\!\left(\frac{\ln(1/\epsilon)}{1-\gamma}\right)$。

**在 LLM 上不可用的三个理由**（这是本节的重点，因为它解释了为什么要学第 4、9 章）：

| 理由 | 说明 |
|---|---|
| **$|\mathcal S|$ 无法枚举** | 状态是 token 历史，组合数天文 |
| **$P$ 未知** | token 级转移虽确定，但"环境"（工具返回）不确定 |
| **奖励只在末端** | 没有稠密 $r(s,a)$ 可供扫描 |

**所以本章的价值不在"用"，而在"读"**：它给了你三个**判据**——模型是否已知、状态是否可枚举、奖励是否稠密。后面所有方法都是在这三点上做妥协的产物。

**回填你的账本表**（第 0 章 0.2 节 · L1 行"标准修法"与 L2 行"方差主源"列）：

```
规划层：已知模型 ✓（本章：评估+改进）、
        GPI 框架 ✓（评估 k 次 + 改进 1 次）
    → 待补：无模型（4 章）、函数逼近（5 章）、
             token 级 MDP（9 章）
```
