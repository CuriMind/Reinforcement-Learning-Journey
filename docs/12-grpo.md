## 12. GRPO：去 Critic 的组内相对优势

> **本章回答的问题**：不训练 critic，怎么知道"这个动作比平均好多少"？组内均值与组内标准差为什么能替代价值网络？省下的显存与算力值多少？——以及最重要的一问：**这个替代什么时候会反噬**。

> **证据强度**：📙 单篇报告 —— 本章最强：GRPO 的目标函数与组内优势定义清晰，已被广泛复现使用；本章最弱：**"去掉 critic 更好"不成立**，它是有条件的取舍，反例见 VAPO（把价值基线加回来）。

> **本章边界**：本章写组内相对优势的定义、与 PPO 的显存/算力对比、rollout 成本模型、以及"去 critic"的适用条件。**不写** GRPO 的缺陷与补丁（→第 13、14 章）；**不写** DAPO/GSPO 的实现细节（→第 13、14 章）；**不写**多轮场景（→第 16 章）。

---

### 12.1 问题：critic 太贵了

> **本节回答的问题**：PPO 在 LLM 上到底贵在哪一步？

PPO 的优势估计需要价值函数：

$$
\hat A_t=\sum_{l=0}^{T-t-1}(\gamma\lambda)^l\,\delta_{t+l},\qquad \delta_t=r_t+\gamma V_\psi(s_{t+1})-V_\psi(s_t)
$$

**逐项读**：① 是 TD 误差（奖励 + 下一状态价值 − 当前价值）；② 是把多个 TD 误差按 $\gamma\lambda$ 加权累加；③ $\lambda$ 控制"偏差—方差"的折中（$\lambda=0$ 纯 TD、$\lambda=1$ 纯 Monte Carlo）。

问题是 $V_\psi$ 必须**与策略同规模**（LLM 上就是又一个 7B 模型），并且：

| 成本项 | 具体开销 | 相对策略网络的倍数 |
|---|---|---|
| 前向 | 每个 token 都要过一次 critic | +1× 前向 |
| 反向 | critic 参数要更新 | +1× 反向 |
| 优化器状态 | Adam 的 $m,v$ | +2× 参数量 |
| 显存 | 权重 + 梯度 + 优化器状态 | 约 +3–4× 模型权重 |

在 7B 模型 + 长上下文下，这一项足以决定"能不能在给定集群上跑起来"。**GRPO 的全部动机就是砍掉这 3–4×。**

> **工程提示**：如果你的显存只够放一个模型，那么问题不是"要不要用 GRPO"，而是"你只能选一种不训 critic 的方案"。另一种是 REINFORCE with baseline（用移动平均当基线），但它在 token 级几乎无用（基线不随状态变化）。

**小结**：critic 的价值在"逐 token、跨 prompt 共享"的精细基线；它的代价是一个同规模模型的全套开销。GRPO 的赌注是：**基线的精细度可以用组内比较来换**。下一节看它怎么换。

---

### 12.2 组内相对优势：用一组样本当基线

> **本节回答的问题**：没有价值函数，凭什么说"这条回答比平均好"？

对同一个 prompt $x$ 采样 $n$ 条回答 $\{y_1,\dots,y_n\}$，得到奖励 $\{R_1,\dots,R_n\}$。GRPO 的优势定义为：

$$
A_{i,t}=\frac{R_i-\mathrm{mean}(\mathbf R)}{\mathrm{std}(\mathbf R)}\quad\text{（常写作 } \tilde A_{i}\text{，对该条回答的所有 token 相同）}
$$

**逐项读**：① $R_i$ 是第 $i$ 条回答的**末端奖励**（整条只有一个数）；② 减去组内均值 = "比这组的平均水平好多少"；③ 除以组内标准差 = 标准化，让不同 prompt 的优势尺度可比。

**它是控制变量（control variate）的一个特例**：用组内均值 $\bar R$ 代替 $V(s)$ 作为基线。控制变量的方差缩减量取决于"基线与目标的相关性"——相关性越高，缩减越多。

| 基线 | 精细度 | 额外成本 | 什么时候准 |
|---|---|---|---|
| 价值网络 $V_\psi$ | 逐 token、跨 prompt | 一个同规模模型 | 状态空间可学、奖励稠密 |
| 组内均值 $\bar R$ | 逐 prompt、组内 | 只需 $n$ 倍采样 | 组内差异显著、$n$ 足够大 |
| 移动平均（REINFORCE） | 全局常数 | 几乎为零 | 几乎从不（忽略状态） |

**方差的关键**在于基线本身的标准误：

$$
\operatorname{Var}\left(\bar R\right)=\frac{\sigma_R^2}{n},\qquad \operatorname{SE}\left(\bar R\right)=\frac{\sigma_R}{\sqrt n}
$$

**逐项读**：① $\sigma_R^2$ 是该 prompt 下奖励的真实方差（题目区分度）；② $n$ 是组大小。它说明两件事：**方差按 $1/n$ 缩小，但标准误只按 $1/\sqrt n$ 缩小**——所以把 $n$ 从 4 提到 16 只能把基线误差减半，代价是 4 倍生成量。**$n$ 越小，基线越不准，优势估计越噪**。这就是为什么 GRPO 的实现里 $n$ 通常要 8–16——它不是"多采点更准"这么简单，而是**基线本身的标准误**。

> ⚠️ **常见错误**：把 $n$ 当作 "batch size" 的替代。$n$ 是**每个 prompt 的组大小**，它决定基线质量；总 batch 是 $n\times$ prompt 数。调大 prompt 数不能改善基线，只有调大 $n$ 才可以。

**小结**：GRPO 用组内均值替代 critic，用 $n$ 倍采样换掉一个模型。基线的标准误随 $n$ 下降，所以"组大小"是它的核心超参。下一节把优势装回目标函数，并算清楚省了什么、花了什么。

### 12.3 目标函数：clip 与 KL 都还在

> **本节回答的问题**：GRPO 的目标与 PPO 到底哪里一样、哪里不一样？

$$
\mathcal J_{\mathrm{GRPO}}(\theta)=\mathbb E_{x,\{y_i\}}\left[\frac{1}{n}\sum_{i=1}^{n}\frac{1}{|y_i|}\sum_{t=1}^{|y_i|}\min\!\left(r_{i,t}\hat A_i,\ \mathrm{clip}(r_{i,t},1-\epsilon,1+\epsilon)\hat A_i\right)-\beta\,D_{\mathrm{KL}}\right]
$$

**逐项读**：① 外层是对 prompt 与组内样本的平均；② 内层是**按回答长度归一化**的 token 平均（注意这个 $1/|y_i|$，它是第 13 章"长度膨胀"的伏笔之一）；③ 与 PPO 完全相同的 clip 项（第 7 章）；④ KL 惩罚仍在，参考策略仍是 $\pi_{\mathrm{ref}}$。

**所以差异只有一处**：$\hat A_i$ 来自组内比较，而不是来自 critic。**clip、KL、重要性比全部保留**。

> **工程提示**：注意 ② 里的长度归一化。它让"长回答的每个 token 权重更小"，**表面上是公平的，实际上引入了长度偏好**——因为长回答的 token 多、梯度总和更大，而 $\frac{1}{|y_i|}$ 又压低了单个 token 的权重。这个矛盾是 Dr. GRPO（第 13 章）要修的东西，现在只需记住：**归一化方式不是细节**。

**小结**：GRPO = PPO 的 clip 目标 + 组内优势。它在目标函数层面没有创新，创新全在"优势从哪来"。下一节算成本——这是它真正的卖点。

### 12.4 成本模型：省下的与花掉的

> **本节回答的问题**：GRPO 到底省了多少、又花了多少？给一个能自己代入的式子。

**总 token 消耗**（rollout 侧，这是 RL 训练的主要成本）：

$$
\text{tokens}_{\text{rollout}}\approx \underbrace{N_{\text{prompt}}}_{\text{每步的 prompt 数}}\times\underbrace{n}_{\text{组大小}}\times\underbrace{\bar L}_{\text{平均输出长度}}\times\underbrace{S}_{\text{训练步数}}
$$

**逐项读**：① 每步用多少 prompt；② 每个 prompt 采几条（GRPO 的基线质量来源）；③ 平均生成长度；④ 总步数。前两项相乘就是"每步生成的回答数"，这是**与你显存和吞吐直接挂钩的量**。

**显存对比**（训练侧）：

| 组成 | PPO | GRPO |
|---|---|---|
| 策略权重 + 梯度 + Adam | $3\times$ | $3\times$ |
| 参考策略（冻结） | $1\times$（bf16） | $1\times$（bf16） |
| **critic + 其梯度 + Adam** | **$3\times$** | **$0$** |
| 显存合计（相对策略） | $\approx 7\times$ | $\approx 4\times$ |
| 每步前向次数 | 策略 + critic | 策略（$n$ 条 + 参考） |

**关键取舍**：GRPO 用"$n$ 倍生成"换掉"一个模型的全套训练开销"。生成是**便宜的并行工作**，训练是**昂贵的串行工作**——这个交换在 GPU 上是划算的，但在推理性任务（输出长、$n$ 大）上会反转。

> **工程提示**：给自己的配置算一遍。若 $\bar L$ 很长（比如 8k）而集群的生成吞吐有限，$n=16$ 可能比一个 critic 更贵。**判断标准是"生成 token 的单价 × $n$" vs "critic 的训练单价"**，不是"谁论文里更快"。

**小结**：GRPO 省的是一个模型的训练开销，花的是 $n$ 倍生成。成本是工程可测的，所以这个取舍没有普适答案——下一节给出判据。

### 12.5 去 critic 是有条件的取舍（不是进步）

> **本节回答的问题**：什么情况下该把 critic 加回来？

反例是明确的：**VAPO**（价值基线 + 长度自适应，📙）在长时域、稀疏奖励的长 CoT 任务上把价值网络加回来，报告了更好的效果。这说明"去 critic"不是普适最优。

判据来自 12.2 的方差分析：组内均值作为基线的质量取决于 $\sigma_R^2/n$，而价值网络的质量取决于"状态是否可学"。

| 条件 | 组内基线（GRPO） | 价值基线（VAPO 类） | 建议 |
|---|---|---|---|
| 奖励稠密、回合短 | 够用 | 过杀 | **用 GRPO** |
| 奖励稀疏、输出很长 | 基线噪声大（$\bar R$ 方差高） | 逐 token 更准 | **考虑 critic** |
| $n$ 能开大（≥16） | 基线变准 | — | **用 GRPO** |
| $n$ 受限（显存/延迟） | 基线很糙 | 不依赖 $n$ | **考虑 critic** |
| prompt 难度差异极大 | 组内可比即可 | 可跨 prompt 共享 | 取决于实现 |
| 全组同分（全对/全错） | **优势全为 0** | 仍有信号 | **必须修采样**（→13 章） |

**最后一行是 GRPO 最尖锐的缺陷**：若某个 prompt 的 $n$ 条回答**全对或全错**，$\mathrm{std}(\mathbf R)=0$，优势全为零，这一步**完全无梯度**——算力白烧。这个现象在训练后期（太难的题全错、太简单的题全对）会越来越普遍，是动态采样（第 13 章）的直接动机。

> ⚠️ **常见错误**：把"GRPO 比 PPO 省显存"讲成"GRPO 比 PPO 好"。**省显存是事实，更好不是。** 正确的表述是：在奖励稠密、组大小可开大、显存受限的设定下，GRPO 的性价比更高；在长时域稀疏奖励下，价值基线仍有价值。

**小结**：去 critic 是一次"用生成换训练"的交易，划算与否取决于四个量：奖励密度、输出长度、组大小、显存预算。把它写成"进步史"是最常见也最有害的简化。下一章开始拆它在实践中暴露的四个缺陷。

### 12.6 本章在粒度账本上的位置

> **本节回答的问题**：GRPO 落在第 0 章那张表的哪一格？

GRPO 是 **L1（bandit）+ L2（token）的混合体**：优势按整条回答计算（bandit 视角），但损失按 token 展开（token 视角）。**这种"跨级"正是它所有缺陷的来源**：

- 整条一个奖励 → 无法区分"中间错了但结果对了"（L3 的问题，第 17 章）；
- 按长度归一化 → 长度成为隐式奖励（第 13 章）；
- 组内比较 → 全对/全错组无梯度（第 13 章的动态采样）。

**回填你的账本表**（第 0 章 0.2 节 · L1/L2 两行的"标准修法"列）：

```
L1: 组内 baseline ✓（本章）  → 待补：全组同分怎么办（13 章）
L2: token 级 loss ✓（本章 12.3）→ 待补：长度归一化的偏差（13 章）
```
